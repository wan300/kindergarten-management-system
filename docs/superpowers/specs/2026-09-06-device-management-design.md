# 小智设备正式开发数据管理设计

## 1. 目标与范围

本功能把已经通过实机验证的小智语音链路从隔离测试数据库接入平台正常的开发数据库，并提供管理员可操作的设备管理页面。管理员无需查找或输入设备编号：开发板访问本机语音服务后自动进入待绑定列表，管理员选择儿童即可完成绑定。

本期交付包括：

- 自动登记首次访问本机服务的开发板。
- 管理员查看待绑定、使用中和已停用设备。
- 管理员将设备绑定到开发数据库中的儿童。
- 管理员停用、重新启用或重新绑定设备。
- 从设备管理页查看该设备产生的儿童聊天记录。
- 语音服务动态读取平台绑定状态，不再依赖启动命令中写死的设备名单。
- 将本机实机链路切换到正常开发数据库并完成验收。

本期不迁移隔离测试库中的虚构儿童、测试账号或历史聊天，不删除隔离测试库，也不部署公网服务器。设备自动升级、批量导入、远程固件管理、跨园区管理和强设备身份认证不在本期范围。

## 2. 使用流程

### 2.1 首次绑定

1. 开发板启动并访问已配置的本机 OTA 地址。
2. 本机语音服务读取协议中的设备编号，并向 Rails 内部接口报告一次“发现设备”。
3. Rails 在正常开发数据库中幂等更新设备的首次发现时间和最近连接时间。
4. 未绑定设备只能出现在管理员的“待绑定设备”列表，不能取得可用的聊天连接凭证、调用 DeepSeek 或产生儿童聊天记录。
5. 管理员进入“设备管理”，选择待绑定设备、班级和儿童，确认绑定。
6. 设备下一次自动重连或重启后通过绑定检查，开始正常语音对话；对话归入所选儿童。

### 2.2 停用与恢复

- 停用只关闭新连接和新对话，不删除设备、绑定关系或历史记录。
- 已建立的连接在下一次授权检查或发送新一轮对话时被拒绝，不能继续调用模型。
- 重新启用保留原儿童绑定，不修改绑定版本；设备重连后恢复使用。
- 已停用设备再次被发现时仍显示为“已停用”，不能自动恢复为待绑定或使用中。

### 2.3 重新绑定

- 管理员可将设备从当前儿童改绑到另一名儿童。
- 改绑在数据库事务中完成，并生成新的绑定标识和递增的绑定版本。
- 旧儿童的会话仍保留并可由有权限的管理员查看，但不会出现在新儿童的上下文中。
- 新绑定从空白设备会话开始；即使开发板复用了外部会话编号，也不能复用旧儿童的聊天上下文。
- 选择当前已绑定的同一名儿童不会无意义地递增绑定版本；若设备已停用，则视为重新启用。

## 3. 数据设计

### 3.1 设备发现记录

新增独立的设备发现记录，保存：

- 规范化后的 `device_id`，全局唯一且不区分大小写。
- `first_seen_at`，首次被本机语音服务发现的时间。
- `last_seen_at`，最近一次被发现或授权检查的时间。
- Rails 默认的创建和更新时间。

发现记录不包含儿童外键，也不代表设备已获准聊天。这样可以继续保持 `ChildDevice`“存在即已有明确儿童绑定”的数据不变量，避免待绑定设备误入儿童业务查询。

### 3.2 已绑定设备

继续复用现有 `ChildDevice`：

- `device_id`：规范化设备编号。
- `student_id`：由管理员选择，设备端不得提交。
- `enabled`：控制是否允许连接和对话。
- `binding_id` 与 `binding_epoch`：隔离重新绑定前后的会话上下文。

发现记录和已绑定设备通过规范化的 `device_id` 关联。列表状态按以下规则派生：没有 `ChildDevice` 为“待绑定”；存在且 `enabled=true` 为“使用中”；存在且 `enabled=false` 为“已停用”。不增加可相互矛盾的冗余状态字段。

数据库迁移只新增发现记录及必要索引，不导入隔离测试库数据。迁移前后都保留平台正常开发数据库中的已有账号、儿童和业务记录。

## 4. 后端边界与接口

### 4.1 语音服务内部接口

新增一个本机内部设备登记与授权接口。它使用现有独立服务凭证，要求请求的实际网络对端为回环地址，并复用固定长度、规范化和日志脱敏规则。

输入只包含语音协议已经验证得到的 `device_id`，输出仅包含 `pending`、`enabled` 或 `disabled` 状态，不返回儿童资料。调用行为幂等：同一设备反复访问只更新 `last_seen_at`。

语音服务在 OTA/连接入口先调用该接口：

- `pending`：完成发现登记，但不签发可聊天连接。
- `disabled`：拒绝连接，不自动更改状态。
- `enabled`：沿用现有短期签名连接流程。

WebSocket 建立时再次检查绑定状态；现有 `/device/turns` 在每轮对话时仍以 `ChildDevice` 为准。三层检查分别覆盖发现、连接和每轮业务请求，停用或改绑不依赖重启语音服务。

如果 Rails 不可用，语音服务拒绝新授权并显示安全的通用提示，不退回小智上游模型，也不把设备自动视为已启用。设备发现请求可在下一次 OTA/重连时自然重试，不对聊天轮次增加自动 POST 重试。

### 4.2 管理员接口

新增仅管理员 JWT 可访问的设备管理接口：

- 设备列表：合并发现记录与 `ChildDevice`，返回状态、设备编号、儿童、班级、首次发现、最近连接及绑定更新时间。
- 首次绑定：接收 `device_id` 与 `student_id`，只允许绑定已存在的儿童。
- 重新绑定：接收新的 `student_id`，通过现有绑定服务旋转绑定标识和版本。
- 停用与重新启用：只更新启用状态，不删除历史记录。

所有写操作使用服务对象和短事务处理并发状态；重复发现、同时绑定和重复点击不得创建重复设备。无效儿童返回未找到或校验错误，过期页面状态造成的冲突返回明确的冲突响应。错误正文不包含密钥、模型响应或数据库内部异常。

教师、家长、儿童和未登录请求均不能访问这些接口。设备端不能指定 `student_id`，也不能直接调用管理员接口。

### 4.3 聊天查询

现有管理员儿童聊天接口保持兼容，增加可选的设备筛选参数。设备管理页点击“查看聊天”后跳转到现有儿童聊天页面，并自动选中对应设备；无记录时显示明确空状态，不创建空会话。

## 5. 管理页面

管理员侧边栏在“儿童聊天”附近新增“设备管理”。页面沿用当前主页和管理后台的深蓝背景、青绿色强调色、圆角卡片、轻阴影与现有字体层级，不引入另一套组件库。

页面包含：

1. 顶部标题、刷新按钮，以及待绑定、使用中、已停用三个统计卡片。
2. 待绑定区域：显示设备编号、首次发现和最近连接时间；点击“绑定儿童”打开表单。
3. 已登记设备列表：显示设备编号、儿童姓名、班级、状态、最近连接和绑定时间。
4. 操作入口：查看聊天、重新绑定、停用或重新启用。

绑定表单先选择班级，再从该班儿童中选择目标，支持按姓名或学号查找。确认区域同时显示设备编号和目标儿童，避免误绑。重新绑定和停用使用二次确认，并明确说明历史记录保留、新绑定不会继承旧对话。

页面在窄屏下改为纵向卡片；按钮保留可见文字和图标，状态不只依赖颜色表达。加载、空列表、请求失败和保存中都有明确反馈，写操作期间禁用重复提交，成功后刷新单项和统计数据。

## 6. 正常开发运行配置

Rails 使用仓库原有 development 数据库，不设置隔离测试库的 `SQLITE_DB_PATH`。DeepSeek 密钥继续从本机 macOS 钥匙串读取，桥接凭证继续来自忽略提交的本机运行目录；密钥不写入源码、数据库、日志或 Git。

语音启动器移除必须手工传入设备白名单的要求，改为以 Rails 的发现和绑定状态作为动态授权来源。本期仍限制在明确启用的可信私有局域网地址运行，内部 Rails 接口继续只接受回环请求。

现有隔离联调启动方式和数据库保留用于回归测试，但文档会明确区分“隔离测试模式”和“正常开发模式”，避免同时启动两个 Rails 服务占用同一端口或把测试账号当成正式账号。

切换正常开发模式时不自动创建管理员或儿童，也不复制测试记录。管理员使用开发数据库中已有账号登录；若数据库没有可用管理员或儿童，由现有平台管理流程显式创建。

## 7. 安全与隐私限制

- 自动发现只说明某个设备编号出现在可信测试局域网，不能证明实体设备所有权。
- 未绑定设备不能聊天、调用模型或读取儿童资料。
- 设备编号不是秘密；管理员绑定权限和本机服务凭证才是授权边界。
- 服务凭证使用恒定时间比较，敏感请求头进入现有过滤规则。
- 不记录原始音频，发现接口不接收聊天文字。
- 本期适用于本机开发和受控试用；公网或真实儿童正式部署前仍需 TLS、设备级密钥、安全配对、撤销审计、隐私授权和数据保留政策。

## 8. 测试与验收

### 8.1 Rails

- 发现接口的正确凭证、错误凭证、非回环请求、输入校验和幂等更新时间。
- 管理员接口的登录权限，以及教师、家长、儿童和匿名访问拒绝。
- 首次绑定、同儿童重复绑定、停用、恢复、改绑及并发绑定。
- 改绑后绑定版本递增，旧会话仍归旧儿童，新会话不继承旧上下文。
- 管理列表状态、时间、班级和儿童序列化正确。
- 聊天接口按设备筛选且不泄露其他儿童记录。

### 8.2 Vue

- 路由和侧边栏入口只对管理员显示。
- 三种设备状态、空状态、失败状态和统计数量正确显示。
- 班级/儿童选择、绑定确认、停用、恢复和重新绑定操作正确调用接口。
- 重复提交被阻止，成功和失败提示清晰。
- “查看聊天”带设备筛选跳转到现有聊天页面。
- 前端既有测试和生产构建继续通过。

### 8.3 Python 语音服务

- OTA 首次访问触发一次幂等发现登记。
- 待绑定和已停用设备不能取得聊天连接；启用设备可以连接。
- Rails 不可用时关闭授权，不回退其他模型，不泄露服务凭证。
- 设备停用或改绑后无需重启语音服务即可在下一次检查生效。
- 既有语音桥接、打断、字幕和 TTS 生命周期测试继续通过。

### 8.4 本机实机验收

1. 在正常开发库启动平台和语音服务。
2. 重启当前开发板，使其自动出现在“待绑定设备”。
3. 管理员从正常开发数据中选择一名专用于开发验收的儿童并完成绑定。
4. 开发板重连后完成至少两轮带上下文的真实 DeepSeek 对话。
5. 管理员从设备页进入聊天记录，确认设备、儿童和消息归属正确。
6. 停用设备，确认不能产生新模型调用；重新启用后确认恢复。
7. 改绑到另一名开发验收儿童，确认旧上下文不进入新会话。
8. 重新运行 Rails、Vue 和 Python 的相关测试，并记录仍属于本地开发环境的限制。

验收不会使用真实儿童隐私数据。实机步骤需要用户在场操作开发板和在页面选择目标儿童；代码测试不能代替这部分物理确认。
