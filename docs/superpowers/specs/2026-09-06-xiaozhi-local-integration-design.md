## 2. 已检查的代码依据

- 开源后台已下载到工作区同级 `xiaozhi-esp32-server`，检查版本为 `8a3c2c5`。保留独立 Git 仓库和来源，不把整套源码复制进幼儿园平台。
- 上游提供 Python 最简服务，以及 Java/Vue 智控台等全模块服务。本期只用 Python 服务；不引入另一套用户后台、MySQL 或 Redis。
- 上游包含 Opus/WebSocket、VAD、ASR、TTS 和 LLM provider 接口。
- 上游现有 ASR/TTS 聊天上报依赖 `read_config_from_api` 与智控台配置，不能误认为最简部署会自动同步到 Rails。
- 幼儿园平台已有 `ChildChatSession`、`ChildChatMessage`、管理员聊天管理、儿童/家长访问边界和 `DeepseekClient`。
- 平台当前回复逻辑位于 `ChildApi::ChatMessagesController`；接口是带儿童登录上下文的文字接口，不是设备接口或 OpenAI 兼容接口。
- 板卡源码及配网组件支持读取、保存自定义 `wifi.ota_url`。实际设备固件是否一致，需要实机核实，不能仅凭源码保证免刷机。

## 3. 方案选择

已比较三条路线：保留官方服务并用 MCP 扩展工具；部署开源后台最简版并对接现有平台；部署开源后台全模块再同步两个后台。

选择第二条。MCP 工具调用不能替代完整会话存档；全模块会重复引入用户、设备和聊天管理。最简版负责语音，Rails 继续作为儿童身份、对话上下文和消息记录的唯一业务来源。

## 4. 组件边界与数据流

1. 玩偶通过配网设置得到本机 OTA 地址，再通过 OTA 响应获得 WebSocket 地址。
2. Python 小智服务完成音频接收、语音活动检测和语音转文字。
3. 独立的 `kindergarten` 对话适配模块携带服务凭证、已验证设备标识、会话标识、轮次标识和本轮文字，请求 Rails 内部接口。
4. Rails 根据服务端绑定记录确定儿童，生成/复用会话；复用平台陪伴提示词和 `DeepseekClient`，保存用户文字与 AI 回复。
5. 适配模块把 Rails 返回的回答交给上游 TTS 和字幕发送流程，不在 Python 侧再次调用另一份 LLM。
6. 现有聊天管理读取同一组会话和消息，增加“玩偶”来源标识，不另建聊天记录页面。

平台的现有网页聊天也改为调用提取后的共用回复服务，保持当前请求和响应格式不变。只进行服务于本次复用的局部提取，不做无关重构。

Python 对接模块应与上游语音流程隔离；需要修改连接层传递设备/轮次上下文时，采用少量明确调用点，不使用跨会话全局变量。不要假设修改 LLM 的 `base_url` 就能直接调用 Rails。

## 5. 会话、绑定与错误处理

- 第一版通过本机管理命令显式将一台设备绑定到一个合成的测试儿童，禁止自动绑定真实孩子或默认取数据库第一条记录。
- 新增设备绑定记录：规范化设备标识、儿童关联、启用状态。客户端不能自行指定有效的 `student_id` 绕过绑定。
- 新增设备专用内部接口，不复用儿童账号密码，不放宽现有儿童/家长接口鉴权。内部接口只供本机语音服务调用，校验独立随机服务凭证；日志和 Git 不保存凭证。
- 会话关联包含来源、设备绑定和外部会话标识。绑定更换后开启新会话，禁止继承上一个孩子的上下文。
- 每轮分配稳定且唯一的轮次标识；数据库唯一约束与处理中状态共同防止并发重试重复创建消息或重复调用模型。
- 相同轮次相同输入成功后返回已有结果；相同轮次不同输入拒绝；处理中返回明确可重试状态。不要无限自动重试模型调用，超时不能视为“肯定没有产生费用”。
- 未绑定或已停用设备不进入模型调用；平台不可用、模型密钥缺失或响应失败时，提供简短故障提示，不能退回一个绕过平台的聊天模型。
- 模型失败时保留用户消息及失败轮次状态，允许有界重试但不重复保存用户消息；失败提示不伪装成正常 AI 回答。
- 用户打断播放不等于模型未生成回答。记录含义明确为“生成的回答”，不能标注成“孩子已经完整听完”；完整播放确认不在本期范围。

## 6. 本机环境和语音服务

- 使用独立 Python 3.10 环境，复用电脑已有环境管理工具和音频工具，不修改现有机器人项目环境或全局包源。
- 不使用 Docker；先核对依赖及 macOS 架构兼容性，再安装所需组件。上游推荐的整套依赖较多，不运行文档中的删除既有环境命令。
- 先使用上游本地 FunASR/SenseVoice 与 SileroVAD，中文优先。模型需下载，大小、来源与磁盘空间在安装前检查，不承诺无需下载或完全离线即用。
- TTS 候选为上游 EdgeTTS，仅用于合成测试文本的连通演示；它依赖外部服务，不视为可靠的生产服务。如果不可用，报告原因，不自动购买或切换到新的收费服务。
- LLM 优先复用平台已配置的服务，不复制、打印密钥。缺少有效配置时先完成 mock 验证并明确报告；需要用户在本机安全填写，不能要求在聊天中发送密钥。
- 第一阶段端口拟用 OTA `8003`、WebSocket `8000`；实际启动前检查占用，不能终止无关进程。平台保留已有 `4000` / `3000` 配置。
- 浏览器模拟测试先使用回环地址。实机联调时仅向可信测试局域网开放必要的 OTA/语音端口，内部业务接口保持本机访问；设备地址不能使用 `127.0.0.1`。

## 7. 数据与安全边界

本版仅用于成人演示及虚构儿童身份，不作为真实儿童数据的生产系统。

本地语音识别不会把录音交给云端 ASR，但文字仍可能发送至平台配置的模型服务，回答文字会交给在线 TTS。这些外部流向应在测试说明中明确。

关闭不需要的视觉、声纹、工具调用、长期记忆、第三方日志上报。禁用音频持久保存；临时音频在成功和失败路径均清理。审查上游日志避免记录对话全文和敏感请求头，不能仅设置 `delete_audio` 就宣称没有数据留存。

设备标识/MAC 不是秘密，单纯白名单不是强身份认证。局域网 OTA 签发的连接凭证也不能自动证明实体设备归属。第一版只在可信测试网络使用，限制接入；真实儿童或公网部署前需另行设计安全配对、设备凭证分发、TLS、撤销、访问审计与保留/删除政策。

## 8. 验证与交付顺序

1. 安装独立环境并启动上游最简服务，检查 OTA 与 WebSocket 协议，不先改玩偶连接。
2. 平台服务测试：授权/拒绝、绑定隔离、历史上下文、重复轮次、并发重试、模型失败以及来源标识；模型使用测试替身，不产生真实模型费用。
3. 适配模块测试：设备/会话上下文正确传递、仅发送本轮输入、错误提示和有界超时，无跨儿童消息混入。
4. 合成身份的端到端测试：语音或模拟输入 → Rails 消息 → 回答 → TTS；后台显示同一轮消息。重新运行平台原有测试和前端构建。
5. 把本机页面和具体连接地址交给用户试用，明确哪些是模拟测试、哪些是真实语音结果。
6. 用户在场时记录原设备 OTA 配置，核实配网页面支持自定义 OTA，再由用户确认切换。若必须刷机，单独说明并取得许可。
7. 实机说一句测试话，在平台验证对应记录；失败时恢复原 OTA 配置，确认官方聊天恢复。官方历史不会自动迁移到新后台。

交付包含：独立开源后台目录、最小对接模块、平台改动、可重复启动/停止说明、测试报告、原连接恢复步骤。任何未完成的实机验证均明确列出，不把“服务启动成功”写成“玩偶已接通”。
